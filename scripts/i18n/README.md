# Перевод интерфейса

Ключ перевода — русский текст: `tr('Закрыть')`, с подстановками `tr('Задач: {{n}}', { n })` (`apps/web/src/lib/tr.ts`).
Словари: `apps/web/src/locales/{en,ka}/src.json`. Нет перевода — показывается русский.

Новая русская строка в коде → оберните в `tr()` → `node scripts/i18n/extract.cjs` покажет непереведённые ключи в `work/chunks/` →
переводы пишутся строками `индекс~~English~~ქართული` в `work/tsv/*.tsv` → `node scripts/i18n/merge.cjs`.
Справочные тексты базы (роли, статусы, сигналы…) — строки `русский~~English~~ქართული` в `work/data/*.tsv` → `node scripts/i18n/merge2.cjs`; шаблоны с `{{p1}}` сопоставляются по частям.
`codemod.cjs --apply` оборачивает русские строки автоматически (одноразово), `leftover.cjs` показывает необёрнутые.

## Письма и push на языке получателя
Edge-функции `send-emails` и `send-push` переводят тексты уведомлений из базы (они хранятся по-русски) на язык `users.locale` получателя —
тем же алгоритмом, что `trData` на сайте (`supabase/functions/_shared/i18n.ts`). Словари функций — выжимка из `locales/<язык>/src.json`:
шаблоны с `{{p1}}` и строки, встречающиеся в SQL. После правки словарей или новых текстов уведомлений в миграциях запустите
`node scripts/i18n/server-dict.cjs` и закоммитьте `supabase/functions/_shared/dict-*.json`.
Постоянные тексты письма (кнопка, подвал, названия категорий) — таблица `S` в `send-emails/index.ts` на трёх языках.
Новый текст уведомления в SQL → добавьте шаблон в словари сайта (extract/merge) и перегенерируйте серверные словари.
